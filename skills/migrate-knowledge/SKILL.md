# Migrate Knowledge

## 목적과 경계

외부 프로젝트의 지식 가치가 있는 산출물을 위키 인스턴스의 `Project-Knowledge`로 **복사**하고, 개념 페이지·Q&A·데이터 레지스트리에 통합한다. 기본 동작은 copy-only다. 원본 폴더 이동·삭제·정리는 별도 `archive-project` 작업이며 사용자의 명시적 승인이 없으면 수행하지 않는다.

## 인스턴스 찾기

1. 사용자가 대상 위키 루트를 지정하면 그 경로를 사용한다.
2. 지정이 없으면 `~/.codex/knowledge-wiki.json`의 `vault_root`를 읽는다.
3. 둘 다 없거나 경로가 유효하지 않으면 대상 위키 루트를 물어보고 중단한다.
4. 대상의 `Research-Vault/_wiki/WIKI-RULES.md`와 `INDEX.md`를 작업 전에 완전히 읽는다. 인스턴스 규칙이 이 스킬보다 구체적이면 인스턴스 규칙이 우선한다.

## 1. 입력과 사전 점검

- 원본 폴더를 절대경로로 해석하고 대상 위키와 동일한 경로가 아닌지 확인한다.
- 원본은 전체 과정에서 읽기 전용이다.
- 대상이 Git 저장소이면 branch, clean worktree, 중단된 Git 작업, 원격 fast-forward 가능 여부를 확인한다. 불안전하면 쓰지 않는다.

## 2. 선별 manifest

재귀 목록을 만들고 파일마다 `include` 또는 `exclude`와 사유를 기록한다.

- 포함 후보: 최종 보고서, 공개판 PDF, 구조화된 케이스·소스 노트, 검증된 분석 메모.
- 제외 후보: 코드, 빌드 결과, 캐시, 임시·백업 파일, 자격증명, 비공개 원자료, 공개판으로 대체 가능한 대용량 PDF.
- 포함 파일마다 상대경로, 크기, SHA256을 manifest에 기록한다.
- 민감도나 공개판 여부가 불분명한 파일은 자동 포함하지 않는다.

## 3. 복사와 검증

- 대상은 `Research-Vault/Project-Knowledge/<project-slug>/`다.
- 충돌 파일을 덮어쓰지 않는다. 동일 해시면 중복으로 기록하고, 다르면 새 버전 경로 또는 사용자 판단이 필요하다.
- 복사 후 파일 수·상대경로·SHA256을 manifest와 다시 대조한다.
- `.gitignore` 예외는 민감도와 저장소 공개 범위를 확인한 뒤에만 수정한다.

## 4. 지식 통합

- 복사 자료 전체를 읽고 사실, 원문 주장, 추론, 전망을 구분한다.
- 수치에는 값·단위·기간·지역·분모·출처·방법을 붙인다.
- 기존 개념 1~3개에 흡수하는 것을 우선하고, 인스턴스 상한과 신설 기준을 따른다.
- 반례·조건·모순을 삭제하지 않는다. 해결되지 않은 충돌은 `CONTRADICTS`, 후속 합성이 앞선 합성을 대체하면 `SUPERSEDES`와 lifecycle metadata를 사용한다.
- 날짜 원본 노트는 불변이다. 대체·무효화는 개념·주장·Q&A 같은 파생 문서에만 적용한다.
- 반복 조회 가능한 데이터 출처만 레지스트리에 적립한다.
- `INDEX.md`와 `INGEST-LOG.md`를 실제 통합 결과에 맞게 갱신한다.

## 5. Git 처리

- 변경 파일을 검토하고 허용 경로만 명시적으로 stage한다. `git add -A`는 금지한다.
- 삭제·이름 변경·원본 소스 변경이 있으면 중단한다.
- 원격이 사전 점검 이후 바뀌지 않았을 때만 커밋·push한다.
- 실패 시 자동 rebase·stash·reset하지 않고 review 가능한 상태로 둔다.

## 6. 완료 보고

포함·제외 manifest, 복사·검증 결과, 갱신한 개념·Q&A·데이터 출처, lifecycle 변경, 미해결 질문, 커밋 해시를 보고한다. 원본은 그대로 남아 있음을 명시한다.
